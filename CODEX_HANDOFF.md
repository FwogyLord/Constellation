## Important traps and fixes already encountered

- Several puzzle helpers once scanned in every room, producing random world lines and boxes. Every room puzzle renderer must gate at the very top with `RoomMatch.isMatched()` and the exact skeleton stem.
- Goldor waypoint state can survive an interrupted run when lifecycle depends only on chat. Keep the render-time dungeon, floor, boss, and exact `Goldor` phase gate plus `resetState()`; this prevents stale fixed-coordinate beams and boxes in later rooms or worlds.
- The HUD editor must not list every enabled element. `HudManager.getEditable()` is intentionally limited to `visibleNow()` plus a five-second last-visible grace period. It must also stay unpaused and visually chrome-free so other mods' overlays can be positioned around.
- HUD positions must go through `HudManager.position()` and `setPosition()`, not directly through an element, or most widget moves will be lost on restart. The central persisted coordinates also preserve special element setters such as the dungeon map and clamp legacy off-screen data.
- `TickManager.once` now stores an absolute due tick relative to registration, ported from Devonian `api/Scheduler.kt`. Do not restore global modulo scheduling for one-shot work: it made two-tick checks and 600-tick timeouts fire early depending on the current global tick. One-shot tasks are removed before their callback, allowing the callback to safely schedule the same ID again. Repeating tasks deliberately retain their existing cadence.
- Requeue completion must be keyed to the exact Extra Stats line, never generic world or dungeon exit. Interrupted runs, disconnects, and manual warps must not schedule anything. Keep this feature advisory-only unless the standing safety rule is explicitly changed.
- Exact puzzle stems currently confirmed: `ice-path`, `ice-silverfish-room`, `water-puzzle`, `boxes-room`, `creeper`, and `teleport-pad-room`.
- Never gate water on bare `water`; normal rooms include water-related names.
- `OrionDungeons.java` contained key, door, and rare-drop emoji title prefixes. They were replaced with plain `Key:`, `Door:`, and `RARE DROP:` text. Keep them plain.
- The chime feature is already effectively present through `SecretWaypoints.collect()` and `echoOnCollect`; adding a second secret-chime listener would double-play sounds. The unused `secretChimeCustom` flag was removed from Orion config; old JSON keys are ignored.
- Spirit Bow generic dropped-item matching already existed, but the actual F4 encounter uses a named armor-stand marker. Both paths now exist without duplicate work in the same entity branch.
- Rare mob drops also use named armor stands rather than normal `ItemEntity` names. Keep their detection before `DropEsp`'s 60-block rendering cutoff so an Ice Spray or M7 Skeleton Master Chestplate alert is not missed elsewhere in the loaded dungeon. The seen-entity set resets outside dungeons.
- `doorTracker` was already described as key plus door ESP but only handled chat/doors. Key entity ESP now fills that missing behavior; do not add a redundant key toggle.
- Odin and Devonian differed on M7 relic spawn delay: Odin defaulted to 38 ticks; newer Devonian code used 45. Current implementation deliberately uses the newer 45-tick value.
- The player-position receive hook now exists in `ClientPacketListenerMixin.java`. Teleport Maze can subscribe through `ConstellationClient.instance().packets().register(...)`; keep the solver itself as a separate run.
